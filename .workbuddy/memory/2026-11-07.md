# 2026-11-07 工作日志

## Cloudflare Pages 部署失败修复

**现象**：Cloudflare Pages 报 `The directory specified by the "assets.directory" field does not exist: /opt/buildhome/repo/.vuepress/dist`

**根因**：Cloudflare 配置期望产物在**仓库根目录** `.vuepress/dist`，但 VuePress 2 默认输出到 `docs/.vuepress/dist`（`dest` 默认值 = `path.resolve(source, ".vuepress/dist")`），路径不匹配。

**修复**：`package.json` 的 `docs:build` 加 `--dest .vuepress/dist`（VuePress CLI 原生支持 `-d/--dest`），`docs:preview` 同步改为 `http-server .vuepress/dist`。

**关键约束**：`@vuepress/cli` 会校验 `dest` 不能位于 `source`（`docs/`）内部，否则回退默认目录。输出到仓库根正好规避。

**另一种思路**：不改构建脚本，改为在 Cloudflare Dashboard 把构建输出目录填 `docs/.vuepress/dist`（相对仓库根）。本次选前者，因为用户配置里已是 `.vuepress/dist`。

## 顶栏导航图标

- 新增 `docs/.vuepress/icons.ts` 集中管理内联 SVG 图形数据（lucide 风格，ISC 协议，与主题内置图标集一致）
- `docs/.vuepress/navbar.ts` 中英文每个导航项加 `icon: { svg: ... }`

**为什么用内联 SVG 而非 iconify 名称**：
1. 完整 `@iconify/json` 包 642MB，太重；单集合包 `@iconify-json/lucide` 仅 665KB 但主题的 `resolveCollect` 依赖 `@iconify/json` 的 `locate`
2. iconify 走远程 API（`api.iconify.design`），构建产物不自包含
3. 内联 SVG 随 HTML 一起 SSR 直出，无客户端闪烁

## 主题机制备忘（vuepress-theme-plume 1.0.0-rc.214）

- 首页区块类型由 frontmatter `config` 数组决定：`banner` / `hero` / `doc-hero` / `features` / `text-image` / `profile` / `posts` / `custom`
- `banner` 类型配置项：`banner`（大图）、`bannerMask`（明暗遮罩 0-1）、`hero`（name/tagline/text/actions）
- hero 文字恒为白色系（`--vp-c-text-hero-name`），浅色背景图需调大 `bannerMask`
- `VPHomeBanner` 默认已全屏（`min-height: calc(100vh - var(--vp-nav-height))`）
- navbar `icon` 字段支持 iconify 名称或 `{ svg: string }`，桌面端与移动端均支持
- 主题内置 lucide 图标以 CSS 形式存在（`vpi-*` class），可作为图形数据来源复用
